# Agent Note：由注册表过滤器强制执行的逐 skill 启用控制

状态：已实现

[English](2026-09-23-skill-enablement-filters.md) | 中文

## 问题

用户若想阻止某个 skill（技能）到达模型，只能删除或编辑其文件，或在 `cordis.yml` 中禁用整个提供方插件。以 GUI（图形界面）为先的 skill 管理需要一个按 skill 名称、可即时生效且可撤销的开关，既能作用于所有项目也能作用于单个项目，并覆盖用户并不拥有文件的随包或远程提供方 skill。

## 决定

`ctx.skills.registerFilter()` 注册一个宿主范围的 `SkillFilter`，其 `resolve(options)` 为一次查找返回一个谓词。注册表在 `list`、`snapshot` 和 `get` 中对合并后的胜出项应用所有过滤器，这些操作决定了模型目录、`skill` 工具、`/name` 调用和浏览器 Session 目录所见的内容。被禁用的胜出项会被直接移除；同名的低优先级候选项不会取而代之，因此禁用一个名称永远不会静默替换成另一份正文。`resolve()` 被拒绝时读取也会被拒绝，使损坏的策略以关闭方式失败。`inventory()` 为管理界面返回每个胜出项及其 `enabled` 和禁用它的过滤器名称，不加载正文。

`dsh-skill-preferences` 是随附的过滤器。它将 `global.disabled` 以及按项目的 `enabled` 和 `disabled` 覆盖列表保存在 `<dshHome>/skill-preferences.json` 中。项目键使用项目 skill 发现所用的根目录，由 `dsh-skill-filesystem` 以 `resolveSkillProjectRoot()` 导出。写入持有跨进程文件锁，通过原子重命名提交，并且只在提交后使目录失效。启动时文件格式错误会阻止插件加载；外部编辑使其格式错误后，所有 skill 读取都会失败，修改操作也会拒绝覆盖它，直到文件被修复。

一次开关通过 `dsh-tool-skill` 现有的目录替换到达正在运行的 Session：`skills/change` 使目录失效，下一步会记录一条替换目录消息，因此模型可见状态仍可从会话日志重建，无需新的事件类型。

## 考虑过的替代方案

**在每个消费方中过滤。** 被否决，因为模型工具、`/name` 预处理步骤、浏览器 Session 目录以及未来的界面都需要相同的检查，漏掉一个消费方就会暴露被禁用的 skill。调用策略决定之所以保留消费方谓词，是因为该策略取决于调用界面；启用状态则不然。

**在合并前过滤，让被遮蔽的同名 skill 接替。** 被否决，因为用户禁用的是其在目录中看到的名称；用另一个提供方的同名正文替换它会是令人意外的替换。

**将偏好存为 profile 补丁中的 `.volatile()` Config 字段。** 被否决，因为以绝对项目根目录为键的按项目覆盖不属于 profile 的插件配置，而且 Config 变更会重新加载注册表及其依赖方，而不是只让一个目录失效。

**将覆盖写入每个项目的 `.dsh/` 目录。** 被否决，因为开关一个 skill 会修改用户的仓库。

## 影响

任何未来的启用来源（例如组织策略）都注册另一个过滤器，并在 `inventory()` 中按名称报告。管理 GUI 读取 `inventory()` 并通过 `ctx.skillPreferences` 写入。注册表单元测试覆盖过滤读取、关闭式失败的拒绝、中止和释放；偏好测试覆盖解析、加锁写入、监视器和文件校验；组装加载器快照证明随附组合会从目录和 `skill` 工具中省略被禁用的 skill，并应用项目覆盖。
